アルトマン氏のRAM発言を皮肉った自動メール送信スクリプトが登場

A Sam Altman parody offers an amusing lesson in memory management

開発者Iain Kay氏が、OpenAIのサム・アルトマンCEOによるRAMに関する発言を風刺したbashスクリプト「Ram-Altman」を公開した。システムのRAMが10%以上空いている場合、1日1回アルトマン氏宛にジョークメールを送信する仕組みだ。

背景：アルトマン氏はPodcast「Cheeky Pint」で、個人のPCにDRAMが眠っていて5%程度しか使われていないのは世界的な資源配分の観点から良くないと発言し話題になった。発言後、同氏はXで表示名を一時的に「RAM Altman」に変更していた。

  • スクリプトは/proc/meminfoのMemTotalからMemAvailableを引いた値（used = MemTotal - MemAvailable）を使用し、ページキャッシュや再利用可能なslabを含める一方、tmpfsや共有メモリは除外する正確な計算方法を採用している。
  • LinuxのMemAvailableはカーネルがスワップなしで解放できる見積もり量であり、単純な「空き」容量より実態に即した指標となっている点が技術的なポイント。
  • 5分おきにカーネルへ状態確認を行い、RAMの空き容量が10%を超えるとランダムなジョークテンプレートからメールを生成・送信するが、送信回数は1日1通に制限されている。

なぜ重要か：著名人の発言を題材にした遊び心あるプロジェクトながら、Linuxのメモリ管理の仕組み（キャッシュと空き容量の違い）を分かりやすく学べる実例として技術者コミュニティで注目されている。

Claude Code、GitHub上で機密情報を意図せず漏洩させていたことが判明

Claude Code is accidentally exposing secrets all over GitHub

AIセキュリティ企業Apiiroの調査により、Claude Codeの設定ファイルがGitHub上の公開リポジトリに流出し、データベースパスワードやAPIトークンなど数千件の機密情報が露出していたことが判明した。

背景：Claude Codeではユーザーがコマンド実行を承認すると、その内容が「.claude/settings.local.json」というローカル設定ファイルにそのまま記録される仕組みになっており、機密情報が含まれるコマンドもそのまま保存されてしまう。

  • グローバルの.gitignoreには当該ファイルが登録されているが、リポジトリ単位の.gitignoreには反映されないため、別マシンへのクローンや後からのリポジトリ化で誤ってアップロードされるケースがある
  • Claude Code自体がユーザーの操作なしに設定ファイルへの変更をコミットする場合もあるとApiiroは指摘
  • Apiiroは10万件以上の公開リポジトリでこの設定ファイルの流出を確認し、うち約1,100件（63組織分）に実際の機密情報（APIトークン、DBパスワード、秘密鍵など）が含まれていた

なぜ重要か：一度発見・削除されても、フォークされたリポジトリに機密情報が残存する可能性があり、AIコーディングツールの利便性機能が意図せず大規模な情報漏洩を引き起こすリスクを浮き彫りにした。
