マサチューセッツ州、データセンターにクリーン電力規制を導入

Massachusetts hits data centers with new clean power rules

マサチューセッツ州のヒーリー知事は行政命令により、25メガワットを超えるデータセンターに対し自前の電力調達とクリーンエネルギー基準の遵守、または電気料金保護基金への拠出を義務付けた。

背景：数年前まで税制優遇などで誘致されていたデータセンターだが、電力需要増大への住民の反発を受け、テキサス州やニューヨーク州に続き規制強化に踏み切る州が相次いでいる。

  • 25MW超のデータセンターは電力需要の100%をクリーンエネルギーで賄う必要があり、自家発電が望ましいとされるが、できない場合は近隣での新規発電施設建設資金の提供か料金保護基金への拠出が求められる。
  • 州は自治体に対しデータセンター事業者との秘密保持契約（NDA）締結を避けるよう指示し、規制実施の準備期間として先月開始したばかりの売上税免除制度の申請を一時停止した。
  • テキサス州（8月、公益事業委員会とERCOTによる監査義務化）、ニューヨーク州（7月、50MW以上の新規建設停止）に続き、3カ月連続でデータセンター規制を強化する州が現れた。

なぜ重要か：AI需要拡大に伴う電力逼迫への世論の反発が政治を動かし始めており、業界側もマーク・アンドリーセン氏らが資金提供する政治団体を通じて反撃を強めるなど、データセンター開発を巡る政策環境が急速に変化している。

アップル、新音声機能のプライバシー保護策を文書で説明

Read the Apple document explaining how new listening features still protect your privacy

アップルはiPhone Duo発表イベントで、Siri Recapやライブリワインドなど新しいSiri AI Audio Intelligence機能を発表するとともに、これらがどのようにプライバシーを保護するかを説明する文書を公開した。

背景：AIによる「アンビエントリスニング」機能の拡大に伴い、マイクから取得する生の音声データがどのように扱われるかへの懸念が高まっており、アップルはその対応策を明示する必要があった。

  • Apple Watch Series 12とUltra 4に搭載されたS11チップの「Secure Exclave」という隔離ハードウェア領域でマイク音声を処理し、生データはファイルとして保存されず、watchOSやアプリ、ユーザー、アップル自身もアクセスできない。
  • 音声はテキスト化や音・音楽の識別に一時利用されるのみで、常に上書きされるバッファとして扱われ、録音データは作成されない。
  • ライブリワインドの起動にはデジタルクラウンの2回押しが必要など、ユーザーが機能の有効・無効を都度制御でき、iPhoneへのデータ転送時は両デバイスのSecure Exclave間で暗号化される。加えてSiri RecapやLive Rewindのテキストはパスコード設定と2ファクタ認証利用時にエンドツーエンド暗号化で同期される。

なぜ重要か：AI機能が常時周囲の音を「聞く」形に進化する中で、専用ハードウェアによるデータ隔離と暗号化を明示することは、ユーザーの信頼獲得やプライバシー規制対応において重要であり、他社のAI音声機能設計にも影響を与える可能性がある。

4 groups caught using the same Chrome and Windows exploit kit

セキュリティ企業Proofpointは、Chromium系ブラウザとWindowsの脆弱性を組み合わせた攻撃キット「BlueMoon」が、中国政府と関係のあるものを含む少なくとも4つのハッキング集団によって使用されていると発表した。

背景：BlueMoonはChromiumの2つの脆弱性とWindows 10（2018年10月更新版）からWindows 11初期版に至る複数OSのカーネル脆弱性1つを連鎖させ、任意のマルウェアを導入できる仕組みで、対象の3脆弱性はいずれも過去24時間以内にパッチが提供された。

  • 通常、貴重な攻撃手法は隠密に使われるが、BlueMoonは検知されやすい形で急速かつ広範に複数の攻撃者間で共有された点が異例。
  • Proofpointは、Chromiumのオープンソース性ゆえに生じる『パッチギャップ』（上流の修正公開と下流ブラウザへの反映のタイムラグ）を攻撃者が悪用した可能性を指摘。
  • AIを活用した脆弱性発見・攻撃コード開発が、こうした高度な攻撃キットの開発コストと参入障壁を下げている可能性がある。

なぜ重要か：AIによる脆弱性発見・攻撃開発の高速化とオープンソースのパッチギャップが組み合わさることで、高度な攻撃能力がより多くの攻撃者に迅速に拡散するリスクが浮き彫りになった。
